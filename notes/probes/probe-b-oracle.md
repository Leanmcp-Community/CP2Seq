# Probe B · 部分状态可行性判据

**状态：完成（2026-09-14）** · 脚本 `workspace/probe-b/`（Node，未改作者源码）

## 结论

**便宜的传播判据在终态层完美，但那是因为终态问题不难，不是因为判据聪明。
→ 论文难度只可能住在序列层。**

## 判据存在，而且是两级

`solver.js:194` 的 `initial_assignment(BA, …)` 接受**任意部分赋值**（`BA` 里 `0` = 未定），
冲突返回 `[type, F, E]`。所以：

| | 代价 | 完备性 | 用途 |
| --- | --- | --- | --- |
| **传播判据** `initial_assignment` | 便宜 | ❌ 不完备 | **免费的、不含 LLM 的剪枝基线** |
| **完全判据** 部分 BA 调 `solve()` | 贵 | ✅ 完备 | 剪枝 ground truth、回溯的 `j` |

## 三个实验

| | 结果 |
| --- | --- |
| 12 个真实无解 CP（`examples/unsatisfiable/`） | 传播判据 **12/12 抓到，0% 假阳** |
| 4,520 次人造部分赋值，2,158 个真不可解（种子 20260914） | **0 假阳** |
| **612 个 CP，数搜索中的死路**（埋点 `SOLVER.propagate` 返回 `[]`） | **95.1% 找到首解时零回溯**，总死路 120，单 CP 最多 16 |

第三个实验是关键诊断：0% 假阳太干净，必须排除「实例根本不需要搜索」这个解释。**没排除掉。**

## 推论

- 终态层 LLM 加不了价值 —— 免费算法已经赢了
- 难度在序列层，与 T4（simple folding NP-hard）和「态数 ≠ 序列数」一致
- ⚠️ **0% 假阳不能搬到序列层** —— 传播判据检查层序一致性，**不检查 simple fold 可实现性**，
  必须重测。**那个不完备的缝隙正是 LLM 剪枝唯一可能有价值的地方**

## Harness 校验（在信任任何数字之前做的）

复算作者 CSV 的 `states`：grids **14/14**、instagram **13/14** 精确匹配。
唯一不符的 instagram/012 查证为该行 `limited=10000`，非 harness 错。

校验逼出三个坑，任一漏掉结果都是错的：

1. **必须先调 `CON.build()`**，否则 `SOLVER.infer` 抛异常
2. **`initial_assignment` 与 `guess_vars` 都原地改 `BA`** → 每次调用传副本
3. `batch.js` 的冲突判定 `out[0].length==undefined` 在 `BF.length===3` 时误判 → 改用 `Array.isArray(out[1])`

## 边界

语料偏向 Flat-Folder 处理得好的 CP · 实验一的反例在完整 M/V 下就不可解，比前缀死路简单
