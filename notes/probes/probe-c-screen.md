## 判据（精确，必要不充分）

第一折作用在单层平纸上 → 必须沿一条**贯穿边界到边界的直线** → 单层只能往一个方向折
→ **该线折痕 M/V 必须一致**。纯 simple folding 没有展开操作，所以那条线一定留在最终 CP 里。
**没有这样的线 ⇒ 一定不可 simple fold。**

## 预折痕：把上界再压低 12.6 个百分点

**论证**：纯 all-layers simple folding **没有展开操作**，所以一条折角为 0 的折痕
（FOLD 里的 `F`）在它产出的 CP 里根本不可能存在。**任何真·预折痕都是动作空间之外的动作留下的
痕迹** —— 带这种痕迹却通过了贯穿线判据的 CP，是**假阳性**：判据放过了它，但它本来就不是
simple fold 折出来的。

### 先解决 `F` 的歧义（27 个存疑的已判掉）

`F` 在 FOLD 里既是「折角为 0 的真折痕」，也可能是导出器三角剖分产生的 **facet 伪边**。
上一版把 27 个 CP 挂成「存疑」。**现在判掉了，靠实测不靠假设**：

| 证据 | 结果 |
| --- | --- |
| **三角剖分是整模型级的操作**，没有人只剖一个面 | **没有任何一个 CP 是全三角剖分的**。69 个含 F 的 CP 里三角面占比最高的是 `058_ku_Color-change_Pinwheel_1` 的 **90.9%** —— 而这个比例在鸟基/蛙基类作品里就是正常几何，不是导出痕迹 |
| 单条边的 facet 特征（两侧面都是三角形） | 只有 **918/10,827 = 8.5%** 的 F 边符合，而且**没有任何一个 CP 的 F 边全部是这一类** |

→ **这批语料里 facet 污染为零。每一条 `F` 边都是真折痕。** 27 个存疑的全部转为假阳性。

脚本仍然单独统计 `fFacet`（可疑边）和 `fSpan`（贯穿的 F 线，最强证据），结论可复核。

## 预折痕不纳入动作空间（已定 2026-09-15）

**不纳入。** 理由不是嫌麻烦，是它会拆掉这个探针本身：

- 一旦允许 fold-then-unfold，「纯 simple folding 没有展开操作 ⇒ 第一折的线必然留在最终 CP 里」
  这句话失效 → **判据失效 → 34.2%<!--fact:probeC.screenFailPct--> 和后续所有下界一起作废**
- 阶段二的「倒着拆」也失效 —— 不再有「最后一步必是全宽折线」
- 搜索空间从有限的单调拆解变成带撤销的图搜索。T4 证了**不带**撤销就已经 NP-hard

**处理方式**：当作**实测出来的范围边界**报，不建模。这正是上面那 6.0% 的来源 ——
它让论文的范围声明更硬，而不是更软。

## 阶段二 · 完整搜索（代码已写完，**尚未跑**）

`workspace/probe-c/stage2.mjs` · 运行：`bash workspace/probe-c/run-stage2.sh`
输入 = 阶段一留下的 **195 个 CP**（241 通过 − 46 个预折痕假阳性），由
`stage1-verdicts.json` 传递，两个阶段不会走偏。

**为什么正向模拟可行**：all-layers simple fold 把整叠纸沿一条直线刚性翻过去，
所以**永远不会自穿透，也没有任何层序约束**。可折性因此是纯几何问题，
不需要层序组合 —— 这正是能从方纸直接正向搜的原因。

**状态** = 一组**层**，每层带 (当前平面里的多边形, 原纸坐标↔当前平面的等距变换, 翻面奇偶性)。
**一折** = 用直线切开每一层、把动的那半反射过去、奇偶性取反；
直线在每层上截出的弦回拉到原纸坐标，**就是这一折造出的折痕 —— 一折一次造出多条**。
这个非局部耦合就是问题难的地方。

**剪枝**（让搜索有限的关键）：一折造出的每条折痕都必须已经在目标 CP 里、位置对、M/V 一致。
候选直线只取目标折痕线的像 → 分支因子是**目标折痕线数**，不是全平面的直线。

**M/V 不用分支**：一折只有一个方向。奇偶性 0 的层往上折写 V、翻过面的写 M，往下折相反。
方向直接从目标读出来再查一致性。

**三分报告，三者含义不同**：

| | |
| --- | --- |
| **SOLVED** | 找到序列 |
| **EXHAUSTED** | 搜索空间穷尽仍无解 ⇒ **证明不可折** |
| **TIMEOUT** | 用尽预算，状态未知。T4 保证这一桶非空 —— **单独报，绝不并进 EXHAUSTED** |

**预算按 query 数（模拟折叠次数）而不是墙钟**，所以数字可复现 ——
而 query 数正是论文效率主张要对标的纯搜索基线。

冒烟测试（已验证能跑，不是结果）：`009_ku_Unassigned_Triangle_Pleat` → SOLVED，
176 queries / 9 步 / 9ms；`001_traditional_Sailboat` → 5 万 queries 用完仍 TIMEOUT（119ms）。
**难度立刻显现，符合 T4 的预期。**

⚠️ 正式跑之前把 `--budget` 定死，之后引用的数字都要用同一个值。

## ⚠️ 第一次跑出来的结果是错的 —— 记下来，因为教训比结果重要

第一版报出 **EXHAUSTED 155 / SOLVED 2**，数字**和最终结果几乎一样**。
但它是错的：三个几何 bug。**如果当时直接写进论文，没人看得出来。**

发现的办法是**往返测试**，不需要任何 ground truth：
**用我们自己的模拟器随机折出一个 CP，再丢回搜索。** 这种 CP 按构造可折，
**除 SOLVED 外任何结果都是 bug**。第一次跑 12 个里错 7 个。

三个 bug，一个藏在一个后面：

1. **生成器造出自相矛盾的 CP** —— 同一线段既 M 又 V（折过去又折回来）。
   真实 CP 只记录最后一次方向。这种 CP 谁都解不了，**看起来完全像求解器的 bug**
2. **`buildTarget` 把折痕区间存进了各自边的方向系**，而不是共享线的方向系。
   `lineOf` 规范化法向量但不规范化方向 → 顶点顺序相反的边差一个符号 →
   一半折痕被镜像记录、看起来落在线上别处 → 下游表现为「真实序列上的 M/V 矛盾」
3. **每层静止的那一半被原样推回、没裁剪** → 层永远不变小 → 后面的折去折一块已不存在的纸

另外修了：`clip` 保留零面积碎片（一层被同时算在折线两侧）；
DFS 换**迭代加深**（原来一头扎到深度上限，把 4 折的 CP「解」成 24 折）；
「必须覆盖新折痕」剪枝**不成立**（不产生新折痕的折仍可重排层序），改为按状态判重。

**`run-stage2.sh` 现在把往返测试当闸门，不过就不往下跑。**

## 可信度：往返测试覆盖到哪、不覆盖到哪

| 规模 | 结果 |
| --- | --- |
| 2–6 折 / ≤23 条折痕 | **25/25 SOLVED**，且**恢复出的序列长度与生成序列完全一致** |
| 8–12 折 / 37–157 条折痕 | 2/15 SOLVED，13 个 **TIMEOUT** |

**关键性质：40 次往返里从未出现过一次假 EXHAUSTED。** 失败一律是 TIMEOUT。
所以 **156 个 EXHAUSTED 是可信的**（搜索在深度 2–5 就真的封闭了：没有任何合法折可走），
而**搜索在深序列上会力竭**是已知且诚实的弱点。

⚠️ **37 个 TIMEOUT 里很可能有可折的。** 往返测试显示搜索撑不过 ~8 折，
而 PurelandFold 的真实序列是 5–21 步。所以 **1.1% 是「确认可折」的下界，不是真实占比**；

📌 **2026-09-17 更新**：原批次每个 CP 预算 200 万 query，剩 37 个未定。按「超时是预算的陈述、不是问题的陈述」这个意见，把那 37 个用 25 倍预算重跑（`workspace/probe-c/budget-probe.mjs`）。**13 个定了，而且全部需要超过旧预算**（中位 1460 万）。预算确实是约束 —— 但结论往相反方向走了：13 个里 11 个关闭为 EXHAUSTED、只有 2 个找到序列，已证明不可折从 89.3% 升到 **92.3%**，上界从 10.7% 降到 **7.7%**。仍有 24 个在 5000 万预算下未定，而已转化的最高用到 4930 万 —— 就贴在预算边缘，**再加预算还会定掉更多**。
可折的真实比例在 1.1% 和 7.7% 之间。

## ⚠️ query 基线这条产出没拿到

原计划「纯搜索的 query 数按难度分层」**做不了：只有 2 个样本**（5,940 和 256,480）。

**但这本身是个更强的结果**：纯搜索在 195 个候选里只解出 2 个。
论文要的不是「纯搜索要多少 query」，而是**「纯搜索在真实语料上根本不工作」** ——
这正是需要启发式的论据，和 Akitaya 2013 future-work 那段话对上了。

## 模型限制（必须写进论文）

搜索拒绝任何「把某条线折成与 CP 最终方向相反」的折。
所以 **EXHAUSTED = 「不存在任何从不逆向折已有折痕的 simple fold 序列」**，
比「不存在任何序列」略强。**每个 EXHAUSTED 都带这个星号。**
