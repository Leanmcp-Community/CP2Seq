# Probe B 初查 · 部分状态可行性判据（读源码，2026-09-14）

源码：`~/Downloads/flat-folder-main/src/solver.js`（302 行）、`NOTATION.txt`

> **问题**：剪枝 ground truth 和回溯距离误差里的 `j`，都要求能判断
> **「一个部分折叠状态是否还有救」**。`flat-folder-capabilities.md` 当时的结论是
> **「剪枝这条腿悬空 —— Flat-Folder 只判完整赋值的终态」**。

## 更正：这条腿不悬空，Flat-Folder 已经支持部分赋值

`NOTATION.txt:111`：

```
BA0 | for each var:     initial assignment
```

`solver.js:194` 的签名与行为：

```js
initial_assignment: (BA, BF, BT, BI, FC, CF, CC, trans_count) => {
    ...
    for (const [i, a] of BA.entries()) {
        if (a != 0) { level.set(i, a); BP[i] = []; }   // 0 = 未赋值
    }
    ... // 约束传播
    return [type, F, E];   // 冲突：哪类约束 + 哪几个面
    ...
    return BA;             // 无冲突：返回传播后的 BA
}
```

**`BA` 里 `0` 就是「这个变量还没定」。** 函数接受任意部分赋值向量，
做约束传播，冲突则返回 `[type, F, E]`，否则返回传播后的 `BA`。

`EF_EA_Ff_BF_BI_2_BA0`（`solver.js:181`）只是**从 M/V 边赋值构造 BA0 的一种方式**，
不是唯一入口 —— `initial_assignment` 本身是通用的。

## 所以我拿到了两级判据，不是一个

| 判据 | 怎么拿 | 代价 | 完备性 |
| --- | --- | --- | --- |
| **传播判据** | `initial_assignment(部分 BA, ...)` | 便宜 | ❌ **不完备**。无冲突 ≠ 有解（只是单元传播，不是完整搜索） |
| **完全判据** | 用该部分 BA 调 `solve(...)` | 贵（= 穷尽搜索） | ✅ 完备 |

**两个都有用，而且用途不同：**

- **完全判据** = 剪枝 ground truth，= 回溯距离误差里的 `j`。
  → `experiment-spec-checklist.md` C 组成立，不用重写
- **传播判据** = **一个免费的、不含 LLM 的剪枝基线** ←
  正好是 C 组基线表下面留白的那个「第四行：不含 LLM 的启发式搜索」。
  **它现在白送到手了，而且比手写打分更有说服力**（是求解器自己的传播，不是我编的启发式）

> ⚠️ **这同时是个风险**：如果传播判据就能吃掉 LLM 的大部分剪枝优势，
> 我的核心主张会被削弱。**但这是现在就该知道的事，不是 rebuttal 阶段才知道。**

## 还剩的缺口（Probe B 未完成的部分）

真正没解决的不是「可行性判据」，而是**更窄的一件事**：

> **一个折叠序列前缀 → 固定了哪些 `B` 变量？**

`B` 变量是**面对面的层序关系**（`BF` = 重叠面对，`FO` = layer order）。
一次 simple fold 会确定哪些面对的相对层序 —— **这个映射要我自己建，它就是 step semantics 本身。**

→ 缺口从「建一个可行性判据」缩小到「建 step→B 的映射」。**范围小很多，但仍是 Probe C 的前置。**

# Probe B 测量结果（2026-09-14，已跑）

脚本：`workspace/probe_b_lib.mjs`（共用 harness）、`probe_b_validate.mjs`、
`probe_b_exp1.mjs`、`probe_b_exp2.mjs`、`probe_b_exp3.mjs`。Node 24，纯 JS，无 API 开销。
**未修改作者源码**（实验三的埋点是在我这边包一层 `SOLVER.propagate`）。

## 步骤 0 · Harness 校验（**先做这个，不然后面的数字都不可信**）

复算作者 CSV 里的 `states`：**grids 14/14 精确匹配**（含 390625）、
**instagram 13/14**。唯一不符的 instagram/012（csv=10000，复算=300608）查证为
**CSV 那一行是带上限跑的**（`limited=10000`），不是 harness 错。

两个过程中发现的坑，记下来：

1. **必须先调 `CON.build()`** —— 它建 `CON.implied`，`batch.js` 在 `main()` 里调。
   漏掉则 `SOLVER.infer` 直接抛异常。
2. **`initial_assignment` 和 `guess_vars` 都原地修改 `BA`** —— 每次调用必须传副本，
   否则试验之间互相污染。
3. `batch.js` 判冲突用 `(out.length==3) && (out[0].length==undefined)`，
   **当 `BF.length===3` 时会误判**。我改用 `Array.isArray(out[1])`，等价且严格。

### ⚠️ 顺带发现的 Probe A 数据缺陷

`instagram_data.csv` 有 **30/366 行 `limited=10000`**（grids 0 行），集中在大档：
**1k–3k 档 15/49（31%）、>3k 档 7/12（58%）**。
这些行的 `states` 是截断值，`solve_sec` 也只是跑到上限的耗时。
→ **方向是低估**：真实状态数更高、真实耗时更长。
Probe A 的定性结论（爆炸在长尾）不受影响，只会被加强，但数字须标注。

## 实验三 · 求解器到底回溯过没有 ← **这才是关键诊断**

0% 假阳太干净，必须先排除另一个解释：**也许这些实例根本不需要搜索，所以没什么可漏的。**

`guess_vars` 里 `SOLVER.propagate(...)` 返回 `[]` 就是撞死路（→ `backtracking=true`）。
`SOLVER.propagate` **只在 `guess_vars` 的两处被调用**（`solver.js:144,166`），
所以数它返回空数组的次数 = 精确的死路数。`lim=1`，即"走到第一个解要撞几次死路"。

**612 个 CP（faces ≤ 400），611 个求解成功：**

| | |
| --- | --- |
| 撞过 ≥1 次死路的 CP | **30 / 611 = 4.9%** |
| 全部死路总数 | 120 |
| 单个 CP 最多死路 | 16（instagram/026，90 面，900 个态） |

> **95.1% 的 CP 找到第一个平折终态时一次死路都没撞过。**
> **在这个语料上，「找一个终态」几乎是无搜索的 —— 贪心就够了。**

## 结论：这既是坏消息也是**把论文范围钉死的好消息**

**1. 传播判据在"终态可行性"这一层是完美的，LLM 在这一层加不了任何价值。**
   它零成本、零假阳。C 组基线表里那个"第四行"不但白送，而且强到没有对手。

**2. 但原因找到了**：终态问题在这个语料上近乎无需搜索（95.1% 零回溯）。
   **完美不是因为判据聪明，是因为问题不难。**

**3. 所以论文的难度不可能住在终态层，只能住在序列层。**
   这和我自己早就写下的两条完全一致，现在有数字了：
   - `flat-folder-capabilities.md`：**态数 ≠ 序列数**
   - Akitaya, *Simple Folding is Really Hard*：**simple foldability 是 NP-hard**

   → **「step → 哪些 B 变量被固定」这个映射不再只是「剩下的缺口」，它就是全部的研究内容。
   难的东西全在那一侧。**

**4. 0% 假阳这个数字不能搬到序列层。** 传播判据检查的是**层序一致性**，
   不是**simple fold 可实现性**。序列层上它会以另一种方式不完备。
   **step semantics 建好之后必须重测，不能引用这里的数字。**

## ⚠️ 这批结果的边界（写论文时必须原样带上）

- 实验二用的是**均匀随机**的部分赋值，不是**序列前缀**那种结构化赋值。
  测的是随机承诺分布下的上界，不是真实分布。
- CP 规模受限：实验二 ≤ 600 面，实验三 ≤ 400 面。
- 实验三只数**走到第一个解**（`lim=1`）路上的死路，不是枚举全部解的死路。
- 语料是作者自己的 examples，**存在选择偏差**：偏向 Flat-Folder 处理得好的 CP。
- 实验一的 12 个反例在完整 M/V 赋值下就不可解，比"前缀走进死路"简单。
