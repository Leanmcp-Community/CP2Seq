# Flat-Folder 能力清单（核实自源码）

2026-09-14。源码：`~/Downloads/flat-folder-main`。只列能力，不设计实验。

---

## ⚠️ 最重要的一条：它没有「步骤」

**Flat-Folder 是终态求解器。** 输入 CP + M/V 赋值，输出所有合法**平折终态**（层序）。

全库没有 fold sequence / step / 中间态 / simple fold 的概念。不是没找到 —— `src/NOTATION.txt`
的对象模型里就不存在时间轴：

```
V/E/F (CP)  →  P/S/C (overlap graph)  →  B (布尔变量)  →  FO (faceOrder)
```

**没有任何一级带「第 k 步」。**

→ **推论：「模拟器当裁判、判每一步是否合法」这个设定，Flat-Folder 给不了。**
   那个东西要我自己建。「我们建立了一个 surface simulator」这句话里真正要建的就是它。

---

## 能回答什么

| 问题 | 怎么拿 | 代价 |
| --- | --- | --- |
| 有没有合法平折态 | 求解成功/失败 | 一次求解 |
| **有多少个**合法态 | `GA.reduce((s,A)=>s*BigInt(A.length))` · `src/batch.js` | 一次求解 |
| 第 i 个态长什么样 | 每个独立分量选一个 `GI` → 组合 → 导出 FOLD | 便宜 |
| 两个态差在哪 | 差在 `FO`（面对面层序），可直接 diff | 免费 |
| 哪些面互相重叠 | `BF`（重叠面对），所有约束的基础 | 免费 |
| **冲突发生在哪** | 失败返回 `[type, F, E]` = **哪类约束 + 哪几个面** | 免费 |
| 这个 CP 有多难 | `batch.js` 现成管线 → CSV | 一次求解 |

`batch.js` 吐的 CSV 列（**现成的难度轴，作者已替我选好**）：
`vertices, edges, faces, points, segments, cells, eps, variables,`
`taco-taco, taco-tortilla, tortilla-tortilla, transitivity` + 耗时。

**注意 `BigInt`** —— 作者预期态数会溢出 64 位。

### 物理约束一共只有四类

`taco-taco` / `taco-tortilla` / `tortilla-tortilla` / `transitivity`（`src/NOTATION.txt`，`BT0–BT3`）。

这就是「纸不能互穿」的**全部**形式化内容。比我以为的少，而且全是**局部的、组合的**。

---

## 不能回答什么

1. **「这一步合法吗」** —— 没有步
2. **「从 A 态能否一步到 B 态」** —— 态之间无邻接关系，输出是**集合不是图**
3. **任何非平折中间态** —— 二面角只有 0 和 π，部分折叠不存在（那是 Track 2）
4. **M/V 赋值怎么来的** —— 接受 `U` 并求解，但求的仍是终态
5. **厚度 / 材料 / 力学** —— 完全没有

---

## ⚠️ 我笔记里一个混用的概念：**态数 ≠ 序列数**

Flat-Folder 便宜地给**终态数**。但：

- 一个终态可能有**很多条**序列走到
- 也可能有**零条** —— 不是所有平折态都能用 simple fold 折出来（Akitaya,
  *Simple Folding is Really Hard*）

**两者之间隔着一整个未解决的问题。** 之前笔记里这两个词有点混着用，改掉。

---

## 已决定（2026-09-14）：方法赢在**剪枝**和**回溯**

不是提议，不是分解。是这两步：

- **剪枝** —— LLM 提前看出这条路死了，不走到底
- **回溯** —— 失败后知道退回到**哪一步**，而不是从头

### 这个决定和上面的能力清单对上了吗？对上一半

| | Flat-Folder 给不给 | |
| --- | --- | --- |
| **回溯** | ✅ **给，而且给得好** | 失败时返回 `[type, F, E]` —— 哪类约束、哪几个面冲突。**这是 blame assignment 的原料**：冲突面能反查回是哪几步引入的 |
| **剪枝** | ❌ **不给** | 剪枝要求「判断一个**部分**折叠状态是否还有救」。Flat-Folder 只判完整赋值的终态，没有部分状态的概念 |

→ **剪枝这条腿目前是悬空的。** 要么我自己建部分状态的可行性判据，
   要么想办法把「部分序列」编码成一个 Flat-Folder 能判的完整问题。**这是下一个要想的事。**

### 顺带：失败模式是**可分类**的

约束只有四类 → 模型的错误可以按类统计。**验证器带诊断，不是 yes/no 黑盒。**
这对「模型是怎么错的」这个探索步骤是直接可用的。
