## Phase 0 · 可行性探针 —— **在写任何东西之前**

**目的不是拿结果，是找出「哪个数字能让我的立论直接死掉」，然后去测它。**

| 线 | 探针 | 死法 |
| --- | --- | --- |
| **Track 2** | 5 个 state 的刚度方差 | 方差为零 → Track 2 立论要重做 |

**Track 1 的探针不是一个，是三个**，按**能多快杀死论文**排序：

| | 探针 | 状态 | 结论 |
| --- | --- | --- | --- |
| **A** | 爆炸曲线：状态数 / 约束数 / 耗时随 CP 规模怎么长 | ✅ | 爆炸在**长尾不在中位数** → 语料必须分层采样（探针已移除） |
| **B** | 部分状态可行性判据存不存在、多贵 | ✅ | 判据**免费且完美**（假阳性 0%），但正因为**终态问题不难** → **难度在序列层**（探针已移除） |
| **C** | 纯搜索在目标 CP 规模上要多少 query | ✅ | **纯搜索在真实语料上不工作**：195 个候选只解出 2 个（探针已移除） |

**三个探针全部完成。Phase 0 结束。**

Track 1 的探针要找的是一个**窗口**：

```
搜索崩溃的规模  ←—— 论文能站的地方 ——→  LLM 崩溃的规模
```

**窗口的宽度 = 这篇论文的分量。** 窗口如果是空的，就没有论文。

### 窗口找到了，但形状和我预期的不一样

我原以为会量到一条「纯搜索的 query 数随难度上升」的曲线，然后证明 LLM 把它压平。
**实际是：纯搜索在真实 CP 上根本上不了场**（195 解出 2）。

所以左边界不是一个规模数字，而是**一个失败率**。这比曲线更硬 ——
它把「为什么需要启发式」从论证变成了观测。代价是：
**难度曲线只能在合成语料上画**，因为只有那里难度可控、且一定有解。

- 时长：一两周
- 代码：一次性脚本，写完就扔，不要建系统
- ⚠️ **研究里最常见的死法就是跳过这一步，花三个月建系统，最后发现立论不成立**

### 别做的事

- 别建日志系统、别建 eval harness、**别接 LLM** —— Phase 0 一个 token 都不该花
- 别把 Probe C 的脚本写得「将来能复用」。它会被扔掉，写得好看是浪费
- 别在 Probe A 的图上纠结难度轴选哪个（B 组的事）—— 现在只要看爆炸在哪

### Phase 0 的交付物 · 已交付

1. **爆炸从哪开始** —— 状态数 ~100 faces，求解耗时 ~500 faces；**爆炸在长尾**
2. **部分状态可行性判据** —— 有，而且免费、零假阳性。但它太好用，反而说明**终态不是难点**
3. **纯搜索在哪崩溃** —— 在真实语料上直接崩溃：195 个候选解出 2 个

**外加一个没预料到的交付物：动作空间的范围边界被实测出来了。**
真实折纸里 **92.3% 已证明不可 all-layers simple fold**，可折上界 7.7%。
这不是探针的目标，是做 Probe C 时掉出来的，而且它直接支撑论文的范围声明。

**当前位置：Phase 0 结束，准备进 Phase 1。**

⚠️ **进 Phase 1 之前挡着一件事**：合成语料还没生成（`../../DATASET.md` §0）。
真实语料已经被证明撑不起主实验（最好 39 个 CP，最坏 2 个），所以合成语料不是补充，是前提。

## Phase 1 · 冻结主张 + 写实验 spec

Phase 0 的数字回来之后，才有资格写下面三样：

1. **一句话主张**（可证伪的，不是系统描述）
   - ❌ 「我们建了一个 surface simulator，LLM 可以根据反馈 reason 出序列」
   - ✅ 「在带精确验证器的序贯约束满足问题上，LLM 的增益不在提议质量，
        而在提前剪枝和定位回溯；因此 query efficiency 而非 success rate 才是正确的度量」
   - 判据：**能被实验打死。不能被打死的句子发不了方法论文。**

2. **一张假图（figure mock-up）**
   主实验图长什么样？横轴纵轴是什么？**我期望的曲线形状是什么？什么样的曲线会证伪我？**
   → **画不出这张图 = 主张还不够具体。**

3. **实验 spec** = `experiment-spec-checklist.md`（要冻结什么）+ `../../EXPERIMENTS_SETUP.md`（怎么跑）
   相当于软件工程的 design doc，接近心理学的 pre-registration

**这时可以写 abstract / intro 草稿，但作用是逼我把话说清楚，不是为了投稿。**
写不出干净的 abstract = 主张还没想清楚。**它们后面一定会重写。**

## Phase 2 · Pilot（小规模试跑）

**最便宜的模型 + 最小数据集（N≈10）+ 跑完整 pipeline。**

目的是 **debug 管线，不是拿结果**。这一步要发现的是：
- 日志少记了字段
- 验证器接口有歧义
- prompt 有漏洞
- 某个 metric 根本算不出来

⚠️ **Pilot 阶段的结果数字一律不看、不信、不写进论文。**

> **Phase 0 刚刚证明了这条纪律的价值。** Probe C 第一版跑出 EXHAUSTED 155/195，
> 和修完 bug 之后的 156 **只差 1**，但它是错的（三个几何 bug）。
> 抓住它的不是看数字，是**往返测试**：用自己的模拟器折出一个 CP 再丢回求解器，
> 按构造必须有解，所以任何非 SOLVED 都是 bug。
> **数字看起来合理，不构成任何证据。**

> 这就是「瞎烧 token」的正确解法 —— **不是不烧，是在便宜模型上把坑全踩完，再上贵模型。**

## 文档纪律：数字只有一个出处

**问题不是我不小心，是同一个数字被手抄进十个 markdown 文件，没有任何东西把它们和来源连起来。**
改一处、漏九处，然后仓库里两个互相矛盾的数字都写得一样自信。这已经发生过不止一次。

机制而不是自律：

| | |
| --- | --- |
| `notes/facts.json` | **唯一出处**。探针移除后已冻结：其中的探针数值不再可重新生成 |
| 文档里的引用 | 数字后面跟一个隐形标签：`89.3%<!--fact:probeC.provenNotPct-->`（渲染时看不见） |
| `workspace/tools/doccheck.mjs` | 校验每一处引用；`--fix` 直接改写全部过期引用 |

它查四件事：

1. **STALE** —— 带标签的数字和 `facts.json` 对不上。`--fix` 一条命令全改
2. **RETIRED** —— 退休的旧值（`65.8%`、`34.2%` …）**没带标签**地躺在正文里。
   给它打上正确的标签就算通过 —— 于是「我确实是指筛选通过率」变成一个**显式动作**，而不是默认
3. **BROKEN** —— `notes/` 重组打断的路径
4. **UNOWNED** —— 计划类文档没写「本文件只负责什么」，这正是两份文件开始描述同一件事的起点

**已经接在 `run-stage2.sh` 末尾**：跑完探针自动刷新 facts 并校验文档。
**结果变了却没改文档，脚本会当场喊出来。**

> 写这个工具的第一次运行就抓到四处我自己漏掉的：`papers.md` 的三个断链（这个文件根本没在我的清单里）、
> 以及当时基线文档里「`34.2%` 的真实 CP 落在动作空间外」—— **实际是 89.3%**<!--fact:probeC.provenNotPct-->。
> **人工核对会漏，这就是证据。**

## Token 纪律（具体几条）

- **确定性优先**：能用规则 / 搜索做的基线，绝不用 LLM
- **缓存一切**：相同 `(prompt, seed, model)` 直接命中缓存，跑第二遍不花钱
- **先小后大**：沿模型能力阶梯往上爬。小模型上做不出信号的实验，
  大模型上大概率也是**设计问题**不是能力问题
- **预算闸门**：每个实验设硬上限，触发即停，人工决定是否继续
- **每次跑之前问一句**：*这次跑完，我会知道什么我现在不知道的？*
  → **答不上来就别跑。**
