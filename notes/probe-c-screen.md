# Probe C 阶段一 · simple-foldability 的必要条件筛选（2026-09-15）

脚本：`workspace/probe_c_screen.mjs`（纯 JS，无依赖，秒级）。语料：instagram 366 个 CP。

> 完整的 all-layers simple-fold 判定对任意 2D CP 是一大坨几何代码。
> **先写一个便宜且精确的必要条件**，看还剩多少个才值得写完整搜索。

---

## 判据（精确，不是启发式）

> 第一折时纸是一整张、单层。所以 all-layers + 无限折线的第一折
> **必须沿一条从边界到边界、贯穿整张纸的直线**；而单层纸只能往一个方向折，
> → **那条线上的折痕 M/V 必须一致**。
>
> **CP 里没有这样一条线 ⇒ 一定不是 all-layers simple-foldable。**

为什么成立：每一折都会在 CP 里留下折痕，而纯 simple folding 没有「展开」操作，
所以第一折的那条线一定还在最终 CP 里。

⚠️ **必要不充分** —— 通过筛选不等于可折。

---

## 结果

| | |
| --- | --- |
| 有贯穿边界到边界的折痕线 | 307 / 366 = 83.9% |
| **…其中至少一条方向一致（U 当通配）** | **241 / 366 = 65.8%** ← **simple-foldable 的上界** |
| …严格一致（线上完全没有 U 边） | 237 / 366 = 64.8% |
| **失败 ⇒ 已证明不可 simple fold** | **125 / 366 = 34.2%** |
| 　其中：连贯穿线都没有 | 59 |
| 　其中：有贯穿线但没有一条方向一致 | 66 |

**规模画像**：通过者面数 p50 = **174**，失败者 p50 = **477**。
→ **复杂作品用不了 simple fold**，与直觉一致。

---

## 两个健壮性检查（做在报数之前）

1. **边界标注**：366 个文件**全部**含 `B` 边 → 边界顶点识别可靠
2. **`U` 边**：语料里有 3,813 条方向未指定的边。最初的脚本直接忽略它们，**这会两头偏**。
   改成把 `U` 当通配（M+U 或 V+U 的线仍算一致），并同时报严格版。
   实际影响很小（**只有 9/366 个 CP 含 U**，上界从 64.8% 动到 65.8%）→ **结论稳健**

`edges_assignment` 取值分布：V 196,550 / M 190,173 / B 21,262 / F 10,827 / U 3,813。

⚠️ 两个 CP（`009_ku_Unassigned_Triangle_Pleat`、`012_ku_4x4_Grid_Unassigned`）的
`creases=0` —— 它们的折痕**全是 U**，是靠通配才通过的。引用时单独标注。

---

## 这个数字本身就是产出

> **至少 34.2% 的真实折纸作品，已被证明无法用 all-layers simple fold 折出。**

它直接支撑论文的范围声明：选 simple folding 不是「覆盖了全部折纸」，
是**覆盖了其中一个可严格界定的子类**，而这个子类的边界现在是实测出来的，不是猜的。
