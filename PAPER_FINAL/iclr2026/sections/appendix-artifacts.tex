\subsection{Dataset generation}
\label{app:generation-procedure}

{\small\begin{verbatim}
GENERATE(reference_depth, action_model):
    state <- unfolded square
    actions, frames <- [], []
    for step in 1..reference_depth:
        candidates <- LEGAL_FOLDS(state, action_model)
        if candidates is empty: return FAILED
        action <- SAMPLE(candidates)
        state <- APPLY(state, action)
        actions.append(action)
        frames.append(state)
    cp <- CREASE_PATTERN_IN_ORIGINAL_SHEET(state)
    cp <- SPLIT_EDGES_AT_INTERSECTIONS(cp)
    if not REPLAY_CHECK(cp, actions, state): return FAILED
    return (cp, state, actions, frames, METADATA(actions))
\end{verbatim}}

\subsection{Evaluation pipeline}
\label{app:evaluation-pipeline}

{\small\begin{verbatim}
EPISODE(sample, model, condition, query_budget):
    cp, target <- LOAD_INPUTS(sample)
    session <- INITIALIZE(cp, target, unfolded_square)
    history <- []
    for query in 1..query_budget:
        obs <- OBSERVE(session, condition)
        call <- model(cp, target, obs, history, condition)
        if call is finish: break
        # Edits: add/remove fold, go to step, restore revision.
        # Reads: state, images, candidates, target feedback.
        result <- DISPATCH_TRANSACTIONALLY(session, call)
        # Rejected edits leave session unchanged but consume a query.
        # Read calls consume a query without changing the sequence.
        history.append(call, result)
        if STOPPING_RULE(session, history): break
    return SCORE(REPLAY(session.actions), REFERENCE_AT_SCORING(sample))
\end{verbatim}
}

\subsection{Protocol failure accounting}
\label{app:protocol-failures}
All 360 planned Luna ablation cases enter the solve-rate denominator. Of these,
355 have completed episodes. Two cases end at the request input-size limit:
\texttt{mid-0006} for GPT-5.6 Luna low with automatic feedback and GPT-6 Luna low
with legal enumeration. GPT-6 Luna low with legal enumeration on \texttt{mid-0010}
ends in a service prompt rejection. For GPT-6 Luna low with automatic feedback,
\texttt{mid-0006} and \texttt{mid-0010} were omitted from the restarted batch after
these blocking errors. These two cases are classified as omissions after blocking errors;
no direct service error is recorded for them in that condition. All five cases
count as unsuccessful evaluations under the planned protocol.

\paragraph{Comparison-tool defect.} The target-comparison tool aligns stacks by their bottom
layer. When no rigid motion aligned the two bottom layers and the layer counts were equal, it
reported the diagnosis \emph{matches} with zero matching layers. Scoring uses a separate
comparator and was not affected by this defect. Replaying the final state of every incorrect
submission made under a comparison condition shows that five followed this false report:
\texttt{easy-0001} in the automatic-feedback ablations for GPT-5.6 Luna (low) and GPT-6 Luna
(high), and \texttt{easy-0001}, \texttt{easy-0058} and \texttt{easy-0095} in the earlier on-demand
comparison runs.

Inspecting final states does not bound the defect's effect: a wrong diagnosis at any turn can
redirect the rest of the search, and the correction need not only add solves. We therefore
audited every comparison a model was shown, on demand or attached automatically, in every run.
For each call we replayed the accepted sequence recorded with it, recomputed the comparison with
the corrected tool at the same tier, and recorded any change in diagnosis or in the number of
matching layers. Of \pending{C} calls in \pending{E} episodes, \pending{c} differ, in \pending{e}
episodes; \pending{e$_a$} of these are Luna ablation episodes (all in condition A). The comparison
tool, like the submitted scorer, used $E_{\mathrm{plane}}$; \pending{q} calls reported
\emph{matches} on a state that is plane- but not identity-equivalent to the target.

We reran every affected ablation episode with the corrected tool, under the original protocol
(80 turns, full image history, same model and effort). Table~\ref{tab:feedback-reruns} gives the
original and corrected outcomes side by side; the corrected outcome replaces the original in
Table~\ref{tab:luna-ablations}. The earlier on-demand runs used other budgets and are reported as
measured, with the \pending{e$_o$} affected episodes marked.

\subsection{Matched baselines and trajectory analysis}
\label{app:matched-trajectories}

\paragraph{Baselines.} We ran two baselines on exactly the 40 ablation
instances, with the same action space and legal-fold enumerator as the models and the same
success criterion ($E_{\mathrm{id}}$), and with every budget stated (Table~\ref{tab:matched}).
\emph{Random-legal} applies a uniformly random legal fold at each of 80 steps (the model's turn
budget), restarting from the flat sheet when no fold is legal or the stack exceeds the target's
layer count; success is checked after every fold, which is more generous than the model, which must
decide to submit. We run 100 such episodes per instance. \emph{BFS} expands distinct states
(keyed by layer polygons, parities and sheet regions) breadth first, to the reference depth plus
four, under a 600-second wall-clock cap; we record the expansion at which it first reaches a
solution, and read off solves at budgets of 80, $10^3$, $10^4$ and $10^5$ expansions.

\paragraph{Failure categories.} Each unsuccessful episode is assigned the first of four mechanical categories that applies.
\emph{F1, state tracking}: more than half of the proposed folds are geometrically illegal in the
current state (tearing, no crease, nothing to move, impossible direction, invalid selection).
\emph{F2, off pattern}: most rejections are legal folds outside the target crease pattern, and the
crease pattern is never completed. \emph{F3, wrong stack}: the episode reaches a state with the
full crease pattern and the target layer count, but in the wrong order, orientation or shape.
\emph{F4, shallow search}: none of the above; the episode never reaches the target depth with a
consistent crease pattern. The categories are descriptive. They separate where in the task an
episode broke down, not which internal capability failed.

\subsection{Ablation sample selection}
\label{app:sample-selection}
\paragraph{Sample selection.} Sample IDs are assigned in generation order, which follows
consecutive generator seeds (\texttt{easy-0001}--\texttt{0010} use seeds 20260918--20260927); the
corpus manifest was written on 17 September 2026, before any ablation run (from 23 September), so
the selection could not depend on model performance. The selected samples match their groups in
reference depth (mean 6.2 vs.\ 6.8 folds on easy, 11.9 vs.\ 12.0 on medium, 16.4 vs.\ 16.2 on hard,
5 vs.\ 5 on some-layers) but are somewhat simpler in final layer count (26.4 vs.\ 33.0 on easy,
116 vs.\ 134 on medium, 860 vs.\ 933 on hard, 10.5 vs.\ 11.6 on some-layers) and in crease count.
If anything, solve rates on the selected samples overstate those on the full groups.

\paragraph{Sensitivity to the cycling limit.} Replaying the logged trajectories, a stricter
limit of two repeats would have stopped \pending{n} episodes earlier, \pending{m} of them
eventually solved. A looser limit cannot be replayed, because the episodes were not observed
past their stop; we therefore reran GPT-6 Luna (high effort, A) on its 40 instances with a limit
of six repeats. \pending{c} of its \pending{28} cycling stops then end in a solve, and its total
changes from \pending{11}/40 to \pending{s}/40.
