# Two-example Qwen folding pilot

Uses the same `Qwen/Qwen3.5-9B` as `tinker_describe_image.py`. The folding loop now
enables and records model-emitted thinking by default using `qwen3_5`; pass
`--no-thinking` to use the original `qwen3_5_disable_thinking` mode.
Defaults to `easy-0001` and `easy-0002` under
`workspace/corpus/out/release/all-layers/samples`. These are a smoke-test pair,
not a representative benchmark. No training takes place.

The commands below are for the user to execute from the repository root. They
have not been run by the editing agent, in accordance with the workspace's
execution preference. Runtime validation and the two paid episodes are pending.

## Install the additional browser dependency

Keep the existing Tinker, cookbook, and Pillow environment that already ran the
single-image example. The new dependency is Python Playwright plus its Chromium
browser; it uses its bundled driver internally. There is no separate Node project
to install or start.

```bash
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
```

## Validate locally, without Tinker sampling

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/test_fold_pipeline.py
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/check_tinker_protocol.py
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/capture_fold.py
```

The regression tests replay the reference actions **only in the test**, checking
the CP and terminal state, failed-edit atomicity, deletion, backtracking,
revision restoration, PNG output, overlap darkness, and image size limits.
The protocol check tests Qwen3.5 XML tool parsing and image-bearing tool results;
it may download tokenizer/processor files from Hugging Face but sends no Tinker
sample requests. Image preparation writes CP, target and initial-state PNGs to
`runs/prepared/<sample>/`. Inspect those before inference.

## Run the two episodes

With `TINKER_API_KEY` already exported in this terminal:

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/tinker_fold_loop.py --samples easy-0001 easy-0002 --max-turns 40
```

Each example gets up to 40 sample calls, including malformed or truncated turns.
At most one tool call is executed per turn. Truncation is logged and retried at a
larger output budget, up to 8,192 tokens, without executing partial actions.
Truncation at 8,192 ends the episode with `output_token_limit`, preserving all
traces. The loop does not repeatedly resubmit an unchanged prompt at that cap.
Every completed model response is also checked for repetition, before retries
or tool execution. Six occurrences of the same substantive sentence or line
end that example with `repetition_detected`. Matching normalizes case, spacing,
Markdown and list numbering; it requires at least six words and 32 characters
to avoid short labels/coordinates. Occurrences need not be consecutive. Counts
are local to each response, not accumulated across otherwise valid tool turns.
Paraphrases are not matched. Thinking and ordinary output are both checked.
The terminal shows a short stop notice instead of echoing the repetitive response;
the full raw response is retained. The trace UI displays the matched text and
threshold. This is a post-response check: it cannot cancel an in-flight,
non-streaming Tinker sample or avoid tokens already generated by that call.

Regression checks for the observed repetition (no model requests):

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/test_repetition_guard.py
```

The complete history is preserved. If it no longer fits the server-verified
context window, the episode ends with `context_budget`; it is not silently
truncated. API errors are written to `error.json`, and the next example is still
attempted. SDK-level network retries can occur in addition to these sample calls.

All artifacts are under `runs/qwen-9b-<timestamp>/`:

- `prompt.md`, `tools.json`, `config.json`, `capabilities.json`: exact setup.
- `events.jsonl`, `transcripts.jsonl`: model turns, tokens, tool results, errors,
  timing, usage, and estimated cost through the research-observability format.
- `<sample>/cp.fold`, `target.fold`: anonymized geometry given to the model.
- `<sample>/initial/`, `turn-NNN-images/`, `final/`: separate PNG files and manifests.
- `<sample>/turn-NNN-messages.json`, `turn-NNN-prompt.json`, `wire-assets/`:
  conversation, exact text-token chunks, and exact uploaded image bytes.
- `<sample>/turn-NNN-response.json`, `turn-NNN-tool.json`: raw response and tool result.
- `<sample>/seq.json`, `steps.fold`, `final.fold`: generated actions and replayed states.
- `<sample>/result.json`, top-level `results.json`: terminal/CP and sequence metrics.

The model receives native Qwen3.5 tool declarations and uses its XML tool-call
format, parsed by the installed cookbook renderer. The reference `seq.json` is
read only **after** the episode to calculate action edit distance and step-count
ratio. No reference actions or intermediate reference frames are model inputs.

## Tools and semantics

| Tool | Effect |
| --- | --- |
| `add_fold` | Append one all-layers fold using angle index, offset, side and over/under. |
| `remove_fold(step)` | Remove a 1-based fold and replay the remaining sequence; reject atomically if invalid. |
| `go_to_step(step)` | Truncate to N folds; zero returns to the empty sequence. |
| `restore_revision(revision)` | Restore a prior sequence, including an abandoned branch. |
| `get_state` | Return the current sequence and layer polygons. |
| `get_images(step)` | Capture any completed state of the current sequence without changing it. |
| `finish` | End and evaluate the current sequence. |

Successful edits create monotonically increasing revision IDs. Each tool result
reports the revision and fold count; revisions are distinct from sequence steps
and LLM turn numbers. Failed edits do not change the sequence. Generated
`seq.json` includes fold axes, sides, direction, generated crease segments, and
layer counts, making it usable by the all-layers dataset viewer.

`hat-brim/seq.json` illustrates a **different**, partial-layer action space. This
pilot intentionally implements the selected all-layers release's schema.

## Images, dimensions, and the asset limit

The endpoint reported a maximum of **2,097,152 bytes per asset**. This is a byte
limit, not a universal pixel resolution. These project defaults are conservative
choices, not an official recommended Tinker resolution:

- `--render-size 512`: generate each CP/top/oblique/reverse/X-ray PNG at 512×512.
- `--max-image-edge 1024`: resize larger inputs, preserving aspect ratio.
- `--max-image-bytes 1800000`: shrink further until both PNG and the cookbook's
  JPEG encoding fit within this budget. Originals are never modified.

All three options are available on the fold loop and capture script; the last
two are also available on `tinker_describe_image.py`. For more CP detail:

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/capture_fold.py --render-size 1024 --max-image-edge 1024
```

PNG artifacts are lossless. The installed cookbook internally encodes PIL images
as JPEG for Tinker; actual `ImageChunk.data` bytes are checked before every sample
and preserved in `wire-assets/`. This prevents a large original photo from
passing unchecked merely because its source JPEG is small. See the official
[ImageChunk API](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/types/imagechunk/)
for the supported PNG/JPEG payload formats.

## Viewer controls and direct capture

```bash
.venv/bin/python DHEERAJ_WORKSPACE/viewer/server.py --corpus workspace/corpus/out/release/all-layers
```

Open `http://127.0.0.1:8000/corpus`, select a sample and move to a step. **Capture
PNG views** displays top, two opposite oblique views, X-ray, and the CP. **X-ray**
displays the overlap-density image. Click any preview to download its PNG. Both
controls also appear on the search-playback page. Capture pauses playback and
uses the completed step at or before the slider position, not the moving flap.

Both pages expose `window.captureFoldStep(step)` returning PNG data URLs without
moving the slider. The Python bridge uses the same `viewer/capture.js` renderer,
so model and UI images use the same camera conventions. Oblique views have a
small illustrative layer gap. X-ray removes that gap and composites one polygon
per layer with constant opacity; overlap is darker. Images fit each state
independently; numeric geometry carries absolute scale and position.

To inspect the model's generated sequences in this same UI, start the server
with `--corpus DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/runs/qwen-9b-TIMESTAMP`.
Each candidate folder includes the `meta.json` needed by the dataset browser.

To render a saved candidate sequence at a chosen step without inference:

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/capture_fold.py --samples easy-0001 --sequence /absolute/path/to/generated/seq.json --step 2 --out /tmp/fold-capture
```

## Evaluation scope

`cp_match` compares crease geometry and assignments. `terminal_reference_match`
compares ordered layer polygons and parity at fixed coordinates, with a 2e-6
tolerance and cyclic/collinear polygon-vertex normalization. `pilot_match`
requires both. `solved` additionally requires an explicit `finish` call.

This is a strict diagnostic metric. It does **not** implement the rotation,
reflection, repartitioned-face or equivalent-layer-order quotient in the full
`EXPERIMENTS_SETUP.md` specification. A different but valid solution may therefore
fail this metric. The shared zero-thickness engine also does not independently
verify continuous-motion collisions. Neither metric is presented as the full
paper's ACCEPT criterion.

The loop estimates cost at uncached published rates and records image-token
counts from the renderer. These estimates are not billing totals; see
`TINKER_PRICING.md`. The two-example pilot is not an accuracy estimate.

## Read the traces

Start the existing viewer in a second terminal (no Playwright needed for viewing):

```bash
.venv/bin/python DHEERAJ_WORKSPACE/viewer/server.py
```

Open **http://127.0.0.1:8000/traces** and select a run, example and turn. This
page refreshes every five seconds and can follow the newest turn while inference
is running. Disable "Follow newest turn" to inspect an earlier turn. It shows:

- The full conversation supplied to the renderer, including image previews.
- Thinking actually emitted by Qwen, including saved partial thinking on truncation.
- Parsed output, requested tools, and the complete raw model response.
- Executed tool arguments/results and their generated images.
- Sampling settings, timing, tokens and links to the exact encoded prompt,
  uploaded images, token IDs, log probabilities, config, events and transcripts.

The renderer can strip historical thinking when assembling a later prompt; the
"Exact input tokens and uploaded images" section is the authoritative wire input.
New runs save both decoded text and token IDs for every text chunk. Recorded
image-description runs also appear. Older folding runs retain their raw outputs
and inputs, but their disabled-thinking mode cannot be retroactively recovered.
Only model-emitted thinking can be recorded; unexposed model internals are not
available. Input/output files are saved for each call, including failed or
truncated turns. Errors and backtracking remain in the history. These records do
not include private SDK network traffic or model activations.

New trace files per turn: `turn-NNN-request.json` (sampling settings),
`turn-NNN-parsed.json` (thinking, text, tools, usage), alongside the existing
messages/prompt/response/tool files. JSON snapshots are replaced atomically so
the UI can safely read an active run. Run folders are retained until you delete
them. Use `server.py --traces /path/to/runs` for a different output root.

To explicitly request thinking with a larger initial output budget:

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/tinker_fold_loop.py --samples easy-0001 easy-0002 --thinking --max-tokens 8192
```

Local trace API tests (no Tinker calls):

```bash
.venv/bin/python -m unittest discover -s DHEERAJ_WORKSPACE/viewer -p 'test_*.py' -v
```

The terminal trace viewer is also available:

```bash
.venv/bin/python DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/observability/view_trace.py --run DHEERAJ_WORKSPACE/EXPERIMENT_SETUP/runs/qwen-9b-TIMESTAMP
```

The sibling `view_trace_tui.py` and `obs_report.py` provide interactive viewing
and multi-run summaries. The vendored scripts come from the
research-observability skill. Earlier single-image `response.json` runs remain
unchanged; they are image-description examples without folding rewards, so do
not mix them into the folding success-rate denominator. `obs_import.py` is
available for explicit legacy imports after inspecting its `--dry-run` output.

## File map

`fold_prompt.md` is the editable prompt. `tool_schemas.py` declares tools.
`fold_tools.js` owns transactional editing and evaluation around the existing
`engine.mjs`. `capture_fold.py` hosts a local module-only browser bridge and saves
images. `image_assets.py` handles image limits. `tinker_fold_loop.py` runs the
agent and records its history. No new `.mjs` files are required.
